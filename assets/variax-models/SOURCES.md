# Variax model bundle sources

`legacy.vxm.zlib` is a converted model library from **Line 6 Variax Workbench 1.75**.
The bodies and pickups come from the Windows 1.75 installer. The two special
responses come from the Mac 1.75 installer. They were calculated with the
original i386 coefficient library in the offline oracle using the
`load_models` recipe in `scripts/verify_factory_programs.py`. Original
installers, extracted files, and response snapshots stay local.

## Conversion

Run the converter on a local tab-separated `models.tsv` (kind, hexadecimal
ID and path), with the two local response snapshots included. See
[the offline oracle recipe](../../scripts/verify_factory_programs.py).
The converter creates a new file atomically.

```sh
cargo run --offline --locked --no-default-features --example convert_variax_models -- /path/to/models.tsv new-legacy.vxm.zlib
```

The app's version-1 format starts with `VXMODEL1`, then stores grouped,
ID-sorted records with little-endian numbers and canonical flags. A body
record stores the interpolation mode first, then the pickup defaults and
six typed variants. A pickup record places the flags and geometry before
the four circuit values. Each special response stores only the 83 float
fields their calculation supplies. Original resource headers, untouched
object bytes, library code, user presets, and firmware are absent.

The version-1 record stream is zlib-compressed using the locked Rust
compression backend. The distributed 40,383-byte asset has SHA-256
`635c726e8092c095532443c024437594c812ec35bf088eb82b29f74d301d35ec`.


## Offline verification

The 1,148-case #238 sweep inputs and oracle outputs stay in local storage.
To compare every word, give the verifier the numbered preset directory, the
concatenated Workbench output, and the index of the first sweep case. The
recorded #238 run starts at index 5, after the source and the A–D examples.

```sh
cargo run --offline --locked --no-default-features --example verify_variax_models -- --oracle /path/to/presets /path/to/original.packed 5
```

The bundled render and the Java/i386 Workbench oracle both produce
`f90165ede89970a29b94384a663390af5100001e3257df5fecfcca3dba18ef8f`
for the 1,148 programs. The oracle runs the original Workbench Java mapping
and native coefficient instructions offline with an initialized host-libm
adapter on Linux.

The platform checks use a separate generated corpus with no private inputs.
The verifier prints the bundle's SHA-256, the checksum of the independently
oracle-checked drop-D audition, and the digest of 1,148 generated programs.
The generated corpus matches the Workbench oracle on Linux with both the
initialized host-libm adapter and the portable-math adapter. The checksum
depends on the chosen math profile.

| Input | SHA-256 |
| --- | --- |
| Drop-D audition program | `dd5e2acd4c39d28d97c421a764c1927b08acb1106df9599c7b4a4695aca659f5` |
| Generated programs, Linux host math | `debe7587ec72ea5475d71d4704d07ded715f21e266b0f21c0f9c151dc59189f0` |
| Generated programs, portable math | `85bab888a4211a3b8f2c9e26440eae8cdf3425ac2bd8a84a43bcd67d3104214a` |

The macOS ARM64 and x86-64 and Windows MSVC x86-64 Rust libraries cross-built
on Linux contain identical bundle bytes. The native macOS and Windows CI
checks run the portable verifier separately and record the render checksums.

```sh
cargo run --offline --locked --no-default-features --features portable-math --example verify_variax_models
```
