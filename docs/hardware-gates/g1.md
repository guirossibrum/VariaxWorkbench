parent [#112](https://github.com/guirossibrum/VariaxWorkbench/issues/112), gate
issue [#125](https://github.com/guirossibrum/VariaxWorkbench/issues/125).

**G1 is not authorized.** This page is the written procedure the owner may
sign later. Until the form at the end is signed and a separate build opens only
the G1 lock ([#158](https://github.com/guirossibrum/VariaxWorkbench/issues/158)),

in simulation only.

## 1. What the app reads

Stage 1 reads information the Linux kernel already holds in memory. It opens
plain files for reading and nothing else. The complete list:

| Source (read only) | Field | Why |
| --- | --- | --- |
| `/sys/bus/usb/devices/<dev>/idVendor`, `idProduct` | USB vendor/product from the cached device descriptor | find `0e41:4650` |
| `/sys/bus/usb/devices/<dev>/bcdDevice` | device release from the cached device descriptor | report only |
| `/sys/bus/usb/devices/<dev>/product` | product string the kernel cached at plug-in | report only |
| `/sys/bus/usb/devices/<dev>:<cfg>.<n>/bInterfaceNumber` | interface number from the cached interface descriptor | list interfaces 0 and 1 |
| `/sys/bus/usb/devices/<dev>:<cfg>.<n>/driver` (link target name only) | which kernel driver is bound | expect `snd-usb-pod` on 0, `snd-usb-variax` on 1 |
| `/proc/asound/cards` | ALSA card numbers, ids and names | report only |

Not read: `serial`, `descriptors`, `/dev/bus/usb/*` (usbfs), `/dev/snd/*`, MIDI
ports, audio streams. Nothing is written to `/sys` or `/proc`. No driver is
bound, unbound, detached or reloaded.

## 2. Code references: no app-originated request

| Claim | Where |
| --- | --- |
| Stage 1 sees the OS only through a read trait with two methods, `usb_devices` and `sound_cards`. | `src/device_probe.rs`, `trait OsMetadataSource` |
| The decision is made from that data alone; zero, several or malformed matches stop. | `src/device_probe.rs`, `fn recognise` |
| The only implementation in this build is an in-memory fixture. | `src/device_probe.rs`, `SyntheticSysfs`, `SimulatedRig`; `LIVE_BACKEND_AVAILABLE = false` |
| Stage 1 does not touch the USB library path. `rusb::devices()`, `open`, detach and claim live only in the G2/G3 session, behind its own gates. | `src/usb.rs`, `Session::open` → `hardware_gates::run_if_unlocked(Gate::OsDiscovery, …)` |
| Every gate is a compile-time constant with no override. | `src/hardware_gates.rs`; test `every_gate_is_compile_time_locked_and_blocks_its_operation_closure` |
| Nothing runs without an explicit Yes, and a passed stage never starts the next. | `src/device_probe.rs` tests `decline_and_cancel_stop_without_running_anything`, `passed_stage_waits_for_its_own_yes_and_never_advances_itself`; GUI tests `device_check_*` in `src/gui.rs` |

Requirement for the #158 adapter (not written yet): implement
`OsMetadataSource` with `std::fs::read_to_string` / `read_link` on the paths in
section 1 only, route it through `run_if_unlocked(Gate::OsDiscovery, …)`, and do
not use `rusb`, libusb, usbfs or ALSA library calls.

**Unverified:** that reading these attribute files never causes USB traffic.
This is the usual Linux design (the values are cached when the device is
enumerated), but it was not checked: the pinned `v7.2.15` source used in
section 3 is only `sound/usb/line6/variax.c`, and `drivers/usb/core/sysfs.c`
was not read.

## 3. Kernel startup traffic (not caused by the app)

When the PODxt Live is plugged in, Linux talks to it before this app runs.
G1 accepts that as normal OS behaviour. Kernel: `7.2.15-1-omarchy` (modules and
hashes in [linux-transport.md](../linux-transport.md)).

| Traffic | Driver | Label | Evidence |
| --- | --- | --- | --- |
| Standard USB enumeration (descriptor reads, address, configuration) | USB core | unverified here (generic USB behaviour, not traced) | — |
| `SET_INTERFACE` interface 1 → altsetting 1 | `snd-usb-line6` probe for the variax match | verified from source/object code (static) | linux-transport.md, "Property row for interface 1" |
| Startup version request `F0 7E 7F 06 01 F7` on interface 1 | `snd-usb-variax` startup state 0 | verified from source/object code (static) | linux-transport.md, "Identity compare" |
| Activate `F0 00 01 0C 07 00 2A 01 F7` | `snd-usb-variax` startup state 1 | verified from source (static): sent only after a reply for product `0x00070000`; the saved Variax 300/600 identity `0x00070004` fails that compare, so this path is not expected | linux-transport.md |
| Interface 0 setup and any startup messages | `snd-usb-pod` | **unverified** | not traced |

None of these were observed live. "Verified from source" means a static
reading of the pinned `v7.2.15` `sound/usb/line6/variax.c` and the installed
object code; it is not a capture.

## 4. Procedure (for the #158 build only)

1. Use the build from #158. Confirm the app's Device check banner says only
   **G1 open**; steps 2–4 must still show as locked.
2. Plug the PODxt Live (Variax attached, powered) into USB. Wait 10 seconds.
3. Start the app, open **Device check…**, read step 1, choose **Yes** for
   step 1 only.
4. When step 1 finishes, choose **No** for step 2. Close the app.
5. Copy the Report text into issue #125.

### Stop conditions

Stop and report if any of these happen: the app offers to run step 2, 3 or 4;
the app asks for a password or permissions; more than one PODxt Live is listed;
the PODxt Live display, lights or sound change when you choose Yes; the app
shows an error. Unplugging the USB cable is always allowed.

### What is recorded

The Report: stage numbers, gate labels, your Yes/No answers, pass/stop, the
USB vendor/product, the bus path (for example `1-2`), interface numbers and
driver names, and the sound card list. No serial number, preset name, file
path or audio. It is saved in #125 as real-hardware evidence, separate from
simulation results.
