# G4 Linux capture owner card

**Draft · direct owner authorization required.** [#118's DAW test request]
covers the Variax 600 on VDI and an ordinary guitar on Guitar In, one at a
time. Both are candidates for the same PODxt Live USB Record Send 1–2 stereo
pair. The owner must approve this exact procedure before launching the DAW
against the rig or letting the audio server open the PCM.

## DAW route and evidence

Use **native Linux Ardour with the JACK backend through PipeWire JACK**,
with WirePlumber exposing the stock `snd-usb-pod` ALSA capture source.
PipeWire 1.6.9, its JACK bridge, WirePlumber 0.5.18, and their inspection tools
were identified from local packages and manuals. Ardour is the documented DAW
candidate. Verify that a native Ardour executable is already available on the
owner's test host and record its version. If it is absent, stop at that
prerequisite. [Ardour manual] · [PipeWire JACK manual]

The Linux 7.2.15 driver declares one stereo capture PCM at **78125/2 Hz
(39,062.5 Hz)**, signed packed `S24_3LE`, six bytes per frame. The PipeWire graph
rate feeds Ardour's JACK project rate. Use the existing rate, for example
48 kHz, and record both values. An integer-rate graph needs conversion
from the native clock at the ALSA-to-PipeWire boundary. PipeWire documents
device-to-graph resampling. Actual opening, exact native negotiation, and
usable audio after conversion still require owner-run evidence. `39062` or
`39063` alone is an integer boundary, and a 48 kHz graph or clip header only
describes that downstream layer. The installed ALSA SPA module references
`snd_pcm_hw_params_set_rate_near`. Its ability to negotiate this fractional
clock is unproven. [Linux source contract] · [PipeWire properties]

## Set up the approved owner run

1. Record the card revision, time, host/kernel, ALSA, PipeWire, WirePlumber
   and Ardour versions. Use the existing PODxt USB attachment and the
   already-active clean or processed instrument Record Send. Record the tone
   and any send setting already known, with unknowns marked. Use VDI only for
   the first take and Guitar In only for the second. Keep the same tone and
   send throughout. Keep the host defaults and device settings as found.
   [Documented Record Send modes]
2. With no test links, use `pw-dump` and `pw-link -oIv` to locate the
   capture node and its two output ports. Record its `node.name`,
   `object.serial`, `device.id`, ALSA path/card/device and current profile
   from the backing ALSA device. Follow the node's `device.id` to that device.
   Match the card and device 0 to its capture devnode
   `/dev/snd/pcmC<C>D0c`, replacing `<C>` with the observed card number. Use
   `udevadm info --query=property --name=/dev/snd/pcmC<C>D0c` to match its
   physical USB path to the ALSA device. Confirm USB ID `0e41:4650`,
   interface 0 and driver `snd-usb-pod` (kernel name `snd_usb_pod`) on that
   attachment. If needed, use
   `udevadm info --attribute-walk --name` with that same devnode to read
   the interface and device parent attributes described in [G1].
   Endpoint `0x82` comes from the verified driver's source contract.
   Record the actual paths and IDs. A friendly name, ALSA card number,
   default JACK input or sink-monitor port alone does not establish identity.
   Check that the PODxt capture and playback substreams are closed before
   proceeding. Stop if the association is ambiguous or either PCM is open.
3. Launch Ardour with
   `PIPEWIRE_PROPS='{ jack.self-connect-mode = ignore-external }' pw-jack ardour`
   (use the existing native Ardour executable name). Select **JACK** in
   Audio/MIDI Setup and use the running PipeWire graph. In a fresh local
   session, add two stereo audio tracks named **VDI** and **Guitar In**.
   Keep hardware playback and monitoring disconnected and MIDI unused.
   Before arming, use `pw-link -lI` to confirm there are no links between
   Ardour and any hardware input or output. Record the exact source port
   IDs and each track's two input port IDs using `pw-link -oIv` and
   `pw-link -iIv`. Stage the two link commands and their matching unlink
   commands before starting the timer. [Ardour manual] · [PipeWire link manual]

## Record two bounded takes

1. For each take, allow **one attempt, up to 3 seconds of recording and
   30 seconds from the first link attempt to verified release**. Start the
   timer before creating the first link, since either link can wake the
   hardware. With `pw-link <source-port-id> <track-input-port-id>`, connect
   the source's two labeled ports to inputs 1 and 2 of the matching stereo
   track and verify the two exact links. Use a second terminal for the
   observations below. Reserve the final 10 seconds for unlinking,
   suspension and release checks. If the checks cannot fit, stop early.
2. While linked, use `fuser -v /dev/snd/pcmC<C>D0c` to verify that your
   PipeWire process owns the identified capture devnode. In the approved run,
   read the kernel's published status for that substream at
   `/proc/asound/card<C>/pcm0c/sub0/{status,hw_params}` using `cat`. Record
   its running state and actual access, format, channels and rate including the
   parenthesized numerator and denominator. Require `S24_3LE`, two
   channels and `78125/2` on this capture stream. Record `pw-top -b -n 1`
   for the source's format, graph rate and error count, and record Ardour's
   rate. Check for new errors during the take.
   Keep the hardware and graph observations separate. Check the PODxt
   playback substream `pcm0p/sub0/status` remains closed. Stop if the route,
   hardware parameters or capture-only operation cannot be confirmed.
   Configuring the PCM acquires buffers and starting it submits
   isochronous input URBs. [Linux source contract] · [PipeWire top manual]
3. Arm only the linked track, enable Ardour's main Record button and start
   transport. Leave a short quiet lead-in. Pick two separated notes for
   **VDI**, or three for **Guitar In**, then stop within three seconds.
   Note which meters move with the attacks on channels 1 and 2. After
   release, inspect both waveform lanes for the same attacks above the
   quiet lead-in, clipped samples or gaps. Record the map from the exact
   source ports into track 1 and 2 and whether the two lanes are distinct,
   duplicated or one-sided. Two matching lanes can show signal from that
   instrument while leaving physical left/right order unproven. A distinct
   time-locked response on each lane can be reported against its port label.
   Physical left/right needs independent asymmetric source evidence.
4. Disarm the track and remove both test links immediately using
   `pw-link -d <source-port-id> <track-input-port-id>`. Stop transport and
   unlink on any failure, cancellation or limit. Verify the links are gone
   with `pw-link -lI`, the source has suspended, the capture substream
   status reports `closed`, and `fuser -v` shows no holder of that devnode.
   Check the playback substream is still closed.
   A stopped track or idle graph alone does not establish release. If release
   is uncertain, quit Ardour, record what remains, and end the run without
   reopening or restarting the server. Only after verified first release,
   disconnect the VDI instrument and connect the ordinary guitar to Guitar
   In. Repeat with the same verified node and its second track. After the
   second release, save the new session and quit Ardour.

| Observation | Report |
| --- | --- |
| No uniquely bound stereo source or ports in the existing profile | Endpoint missing or identity unresolved. Record the ALSA card and PipeWire observations. Stop before linking. |
| Correct ports exist, but linking or PCM start fails, or the rate/format cannot be confirmed | Negotiation or native-proof failure. Save the exact link error, node state and available hardware parameters. A busy handle is an ownership conflict. |
| Native PCM is running as expected and the DAW has the two links, but notes fail to stand out from the quiet lead-in | No signal for that instrument. If one lane responds, report partial channel evidence. |
| Disconnect, new xrun, suspension during capture, or unexpected route/playback | Stop and record the interruption and release result. |

Keep the new session, takes, observations, frame counts (or clip lengths at
the recorded project rate), and timestamps in a fresh ignored local
`backups/` folder. Record each attempt's input, source-to-track map, rates,
signal outcome, stop reason, elapsed time and release results. Stop the run
after any failure and keep the partial evidence.

## Separate Workbench acceptance (#128)

The current build has no live initializer or authorization issuer for
Workbench acceptance. Its proposed capture remains one unlinked direct ALSA
hardware PCM, one attempt, up to three seconds of capture and 30 seconds
from open attempt to release. The exact request, prepared-handle rational
readback, attachment binding, geometry and channel proof follow the
[Linux source contract]. Open acquires resources with the stream stopped.
Configure and prepare acquire buffers and reset counters. Start submits
isochronous input URBs. Drop clears PCM ownership and unlinks URBs when
there are no other users. Close releases the acquisition and handle.
Record drop and close results separately. Save exact-clock AIFF and sidecar
to new files. Reconcile [#128]'s WAV criterion before seeking separate direct
approval, since WAV requires an integer rate.
