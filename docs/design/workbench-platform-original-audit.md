# Variax Workbench platform and original application audit

## Finding

The Linux owner screenshot of build 21 shows the `WB`, `Variax`, `PODxt` and `HD` text marks. The first three are the shared shell's missing-image fallbacks. The HD500X tile always uses a text mark at this revision. The two tested Linux deliverables carry the shell code and its resource names, but both expect the PNGs under a disposable build checkout that is now gone. The same-head Mac bundle carries the PNGs at the location selected by its executable-relative lookup. The owner Mac captures show the header logo and PODxt pedal art; they show the editor, so the two Mac landing-card images are verified by the package inventory and lookup trace only.

## Effective source-file reuse

The table inventories the repository source paths that decide the workflows above. **L** is the x86-64 Linux release and **M** means both Darwin release slices. **W** is `variax-workbench-gui` and **R** is `rig-check`. A path marked **library** is compiled in the library crate used by the build. Final linking can discard unreachable code. A direct binary module can be attributed to its entry point. A row marked **consumers** gives the runtime call paths compared here. This is a source and build-selection inventory, rather than a claim that every library function appears in both executables.

The module declarations and manifests establish selection. The two owner profiles both enable `gui`, `usb` and `portable-math`. `gui` brings in eframe/egui/Glow, winit, PNG decoding via `image`, `podxt-table`, and `rfd` on non-Mac. The Linux desktop chain uses winit's X11 and Wayland backends and rfd's portal support. Mac uses the Darwin winit backend and a repository-owned Standard Additions adapter for file dialogs. The locked external dependency identities come from `Cargo.lock`. A GUI-only build still compiles file editing and Stage, but removes device panels/transactions selected by `usb`; Linux can still show passive recognition. Both audited releases take `src/math.rs`'s `portable-math` branch with pinned `libm` 0.2.16 and `force-soft-floats`.

`usb` connects the root crate and `line6-devices` through the same repository `rusb` 0.9.4 and `libusb1-sys` 0.7.0 inputs. The Darwin target enables their `vendored` path and compiles the bundled libusb Darwin backend against system frameworks. The Linux owner ELF resolves system libusb through the non-vendored path. The repository's fallback libusb Linux C sources are therefore outside the Linux artifact's compiled inputs. Only Darwin adds `macos-usb-inventory`, whose IOKit and CoreFoundation FFI provides passive enumeration. Both Unix targets use `libc` for the shared lock. Linux RawMIDI uses the kernel-provided device node rather than linking a user-space ALSA MIDI library. `linux-alsa-native`, `owner-reso5-test`, and the test-only screenshot feature are outside the owner build.

For any row, substitute its repository path for `path` below. `git ls-tree -r` on the directory gives the child inventory, while the declaration/branch search identifies test-only modules and target alternatives. Package checksum manifests refer to finished files and are a separate identity check.

```sh
rev=99a62f37e9990fbcdf773162e0f9a6af17f9e4fc
git rev-parse "$rev:$path"
git ls-tree -r "$rev" -- src/app src/families src/shared src/rig_check \
    crates/line6-devices crates/macos-usb-inventory third_party/usb
git grep -nE '^[[:space:]]*#\[(cfg|cfg_attr|path)|^[[:space:]]*(pub )?mod |include_(bytes|str)!' \
    "$rev" -- app src crates
```

### Overlapping operations and consolidation cost

| Maintenance cost | Overlap and evidence | Assessment |
| --- | --- | --- |
| Low | `src/families/podxt/file/library.rs::read_regular_tone` and `src/families/hd500x/file/format.rs::read_regular_hd_editor_file` share literal parameter declarations, metadata error conversion and the regular-file guard. Both use the shared capped reader, with family-specific limits and diagnostics. | Small application-level duplication. Consolidation can reuse the regular-file policy and preserve the supplied family ceilings and messages. No implication of shared formats. |
| Low–medium | `assets.rs::load` and Variax `mod.rs::artwork_texture` separately open a PNG, convert to RGBA, and create a texture. The first validates a relative resource path, returns named placeholders and shares the shell/PODxt resource root. The second caches failures/textures and retains pickup RGBA used by the body scene. | Similar sequence with materially different contracts. Reuse at the decode/texture boundary is plausible after packaging parity. Roots, cache semantics and pickup data retention have separate requirements. |
| Medium | Linux `live_panel.rs::open_platform` and `port.rs::RealPort::podxt` both open RawMIDI. The editor resolves the selected verified attachment anew; Rig Check retains a link across steps. Mac likewise uses `podxt_live.rs::with_workbench_link` vs. `RealPort::open_direct_usb`; the latter manages the rig's cross-step USB lifetime. Variax driver return is Linux-specific and IOKit route correlation is Darwin-specific. | Necessary OS adapters with different consumer lifetime/attachment policies. Share narrowly where invariants match. Removing target-specific open/cleanup behavior would change semantics. |
| Medium–high | Workbench `identity.rs`, `usb.rs`/ `identity_stage.rs`, and Rig Check `steps.rs` all identify a guitar, with different admission, request, retry and cleanup rules. `MacUsbPresence` and the Rig Check Mac collector already consume shared inventory. | Overlapping application policy across separate files, not a literal duplicate protocol. Centralize reply/error classification and transport-neutral fake vectors first. Preserve the G2 request bound and Rig Check's operator recovery as separate policies. [#201](https://github.com/guirossibrum/VariaxWorkbench/issues/201). |
| High | Variax `procedure_device.rs::sync_on` and Rig Check `variax_save.rs::save_own_bytes` share family comparison and store procedures. PODxt editor `store.rs::store_transaction` and Rig Check `podxt_save.rs::save_own_bytes` share the family store state machine, with different source bytes, confirmations, progress and timeout aftermath. Variax editor refresh and Device Check backup also use common family sweeps with different provenance and publication requirements. | Shared protocol logic is already factored. Keep entry-point eligibility, document baselines, diagnostic evidence and owner consent independent. Any further reuse must preserve their failure and recovery semantics. |
