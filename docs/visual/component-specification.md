## Annotated comparisons and measurable layout

[Workflow comparison](workflow-comparison.svg) places a resource-hierarchy
reconstruction beside original guitar and POD proposals. The reference column
is an abstract schematic with original geometry, not vendor artwork or a
screenshot. Numbered rows map global navigation, context, task canvas, inspector,
library and status. The 400-unit diagram columns are explanatory miniatures,
not the application's proposed runtime dimensions.

[State and responsive board](responsive-states.svg) refines dirty prompts,
failed/successful saves, empty library, unsupported controls and compact layout.
Neither board is interactive or proves a working state machine.

Proposed full-size geometry uses 60/48/24-unit global/context/status strips.
At 1280×800, main content is 1030 wide plus a 250-unit library; canvas height 368,
inspector height 300. At 1920×1080 retain a 250-unit library, use canvas 568 and
inspector 380. At 1024×768 the library becomes a modal drawer; canvas 356 and
inspector 280 fill the remaining height. Inspector subcolumns stack if either
would be narrower than 200. A drawer never covers an unacknowledged dirty prompt.
The shell switches at 1200 logical units; saved split positions clamp to current
available bounds before layout. Widths below 1024 remain scrollable: do not
silently shrink text or targets. OS chrome is outside these logical sizes.

Use spacing 4/8/12/16/24, radius 6, body/title 14/18, line 20, target ≥32 and
focus border 2. At 1×/1.5×/2×, multiply logical geometry by pixels-per-point;
never multiply it twice. This is a specification check, not a rendered DPI pass.

Long text checks for later implementation: 120-character filename, 64-character
model label, two-line capability reason, non-ASCII preset names and 200% text
expansion. Wrap labels/reasons; truncate only filenames with full text available
on keyboard focus as well as hover. Value and unit must stay together. Keep
existing source bytes unchanged when display truncates. Actual egui font galleys
must fit available width; SVG system-font substitution is not that measurement.

## Reusable component contracts and state preservation

The stack remains pinned egui/eframe 0.33.3 with default fonts/glow and rfd behind
`FileDialogs`; no CSS/webview, new UI dependency or vendor renderer is proposed.
Names below are future component concepts, not Rust types already implemented.

| Component | Inputs / responsibility | Required boundary and future acceptance |
| --- | --- | --- |
| RigShell + DocumentStrip | Current family, local document/source, dirty state, pending operation | Show offline status on every page. Never start a device/audio backend on navigation. Derive state from existing Workbench/document models; do not maintain a second dirty flag. |
| SplitInspector + ParameterCell | Validated domain, current value/unit, validation error | Keyboard numeric edit and named label accompany knob/slider. Group drag edits through existing history semantics. Unsupported IDs stay read-only; unknown domain never becomes an editable plausible range. |
| FamilyLibraryRow | Family, slot/name/source, local selection and dirty marker | Arrow navigation changes local selection only. Unknown family stays unverified. Malformed open preserves the previous document/selection. No cross-family conversion implied. |
| GuitarCanvas | Body model, two modeled virtual pickup selections, wiring/tuning | Original vector geometry. Label modeled pickups explicitly; physical piezo string sensing is separate. Changing artwork does not change guitar/audio capability. |
| CapabilityNotice | Lock or unsupported-domain reason, optional unavailable action | Two distinct reasons: “Hardware access locked — offline phase” versus “Parameter definition unverified.” Disabled button does not trap focus; adjacent focusable explanation provides equivalent text. No icon-only reason. |
| BlockingDirtyPrompt + SaveFeedback | Existing Pending action, save result, invoking focus ID | Reuse existing save/undo/open/quit behavior and error fields. Success only after save-copy API returns success; failed/cancelled save retains dirty state and pending action. No overwrite implied. |

Source integration anchors are `src/gui.rs`: `Pending`, `save_dialog`,
`request_close`, `continue_pending`, `pod_quit_dialog`, `recording_quit_dialog`,
`save_next_dirty_pod`; and `EditorDocument::save_copy`/history. `request_close`
already gates guitar edits, dirty POD tones and unsaved recording takes in order.
Do not replace that queue with a single visual confirmation. In particular,
“Discard” for one document does not authorize loss of another dirty tone/take.
Preserve existing offline GUI prompt and recording tests before migration.

| Trigger / state | Required visible result | Existing behavior to preserve |
| --- | --- | --- |
| Dirty open/quit | Blocking save/discard/cancel, default focus Cancel | Background edit, navigation and undo shortcuts blocked; no action before explicit choice |
| Save succeeds | Saved new copy + destination, then guarded continuation | Atomic non-overwriting save; next dirty resource can still require a prompt |
| Destination exists / save fails | Copy not saved + reason, choose new path/cancel | Keep edits, selection and pending operation; no success badge or automatic retry |
| Cancel prompt / picker | Return to editing; focus restored to invoker | No write/discard; picker cancel is not a successful save |
| Discard | Explicit local scope, then existing pending continuation | No device/bank switch and no blanket discard of all resources |
| Empty library / bad file | Open local file / persistent parse reason | No synthetic presets added; valid previous document retained on failure |
| Unsupported hardware/model | Readable capability reason, raw ID if available | No fabricated knobs, values, “connected” or “synced” status |

## Keyboard, contrast and acceptance gates

Proposed normal Tab order is navigation → file actions → canvas selection →
inspector category → parameter value → library → status action. Within lists,
arrows move local selection; Enter activates; text fields retain text-edit keys.
Ctrl+S follows the current save API, not a parallel persistence path. In a modal,
Tab/Shift-Tab wraps Save new copy → Discard → Cancel; Escape is Cancel and restores
the invoking ID. For a compact library drawer, Escape closes only that drawer;
a higher-priority dirty prompt retains modal focus. On responsive reflow keep
stable egui IDs based on family/document/slot/parameter, not visible row index.

Contract colors are opaque proposed tokens. Automated solid-color contrast
checks target text ≥4.5:1 and focus ≥3:1; primary/secondary text are checked on
selected surface, error/warning on raised, focus on panel. Selection also needs
a non-color marker. Runtime alpha, theme overrides, native high contrast and
screen readers are separate OS acceptance checks, not certified by this audit.

Future implementation must demonstrate the state table with FakeDialogs and
headless egui input, plus Windows/macOS/Linux native keyboard, screen-reader and
100/150/200% rendered scaling checks. Assert full error/reason text accessible,
focus visible and no clipped value/unit or unreachable button at each specified
size and expanded-label sample. The current static validator checks rectangles,
contrast and SVG safety only; it cannot certify actual focus/label fit/accessibility.
